# Assignment

## Assignment ID

`<project>-<owner>-<sequence>`

Example:

`PH6-SHI-001`

## Owner

The specialist or runtime responsible for this assignment.

## Requested by

Nova

## Priority

Low, normal, high, or urgent.

## Objective

State the exact outcome expected.

## Context

Provide the background needed to understand the assignment.

## Scope

List the repositories, files, systems, environments, or data included.

## Out of scope

List anything explicitly excluded.

## Inputs

List the documents, paths, decisions, logs, or prior outputs required.

## Constraints

State the rules the assignee must follow.

Examples:

- Read-only analysis
- Do not modify files
- No production changes
- Do not expose credentials
- Return findings in chat only
- Use a separate branch or worktree

## Required deliverables

List the exact outputs expected.

## Validation required

Describe the tests, checks, or review steps that must be performed.

## Evidence required

List the proof that must be returned.

Examples:

- Commands executed
- File paths
- Git diff
- Commit ID
- Test output
- Logs
- Screenshots
- Reports

## Dependencies

List required work or approvals.

## Escalation conditions

State when Nova or Gerso must intervene.

## Completion criteria

Define what must be true before the assignment is complete.

## Recommended next owner

Identify who should receive the result next.
