### What was attempted

maintaining and mirroring personal Git repositories, fully GitOps-managed through

### Forgejo deployment

- Deployed Forgejo 15.0.7-rootless (LTS release) using Helm chart 17.1.5.
- Forgejo Helm chart 17.x no longer bundles PostgreSQL, so PostgreSQL was
  deployed separately and pinned to the same node (`niner`) as Forgejo.

- Forgejo PVC: 20 Gi local-path. PostgreSQL PVC: 10 Gi local-path.

  hostPort, hostNetwork, or externalIPs introduced.

- Public hostname: `git.ninjatronics.io` using the existing `homelab-k3s` tunnel.
- Registration disabled. Image tags pinned (not `latest`). Forgejo LTS preferred.
- Secrets stored in [[OpenBao]] at `secret/apps/forgejo`, populated by External
  Secrets Operator into Kubernetes Secrets. No real secret values in Git.
- OpenBao KV v2 policy grants read on `secret/data/apps/forgejo` and
  `secret/metadata/apps/forgejo`.
- A `secret.example.yaml` with placeholders only was retained for documentation.

### Cloudflared ConfigMap reload problem

After adding `git.ninjatronics.io` to the cloudflared configuration, the
ConfigMap reached Kubernetes through Flux, but cloudflared did not reload
automatically. A manual `kubectl rollout restart deployment cloudflared -n
platform` created a new pod on `samson`, but it failed with
`ImagePullBackOff`.

See [[Tailscale DNS SERVFAIL on Kubernetes Nodes]] for the DNS root cause
and [[Kustomize ConfigMapGenerator Rollout Triggers]] for the permanent
GitOps fix.

### Samson DNS incident

- `ImagePullBackOff` on `samson` was caused by Tailscale DNS forwarding
  failure, not Docker Hub rate limiting, a bad image, or K3s networking.
- [[Samson]]'s `/etc/resolv.conf` had been set to `nameserver
  100.100.100.100` (Tailscale Quad100) by Tailscale DNS management.
- Tailscale had no upstream resolver configured, so all DNS queries
  returned SERVFAIL.
- Internet connectivity was healthy (`ping 1.1.1.1` succeeded); only DNS
  forwarding was broken.
- Immediate workaround: `sudo tailscale set --accept-dns=false`, restoring
  `nameserver 10.99.0.1` (LAN resolver). DNS, Docker registry resolution,
  and containerd image pulls all recovered immediately.
- Tailscale networking itself remains operational; only DNS management is
  disabled.
- Future architecture task: decide whether homelab nodes should use
  Tailscale DNS/MagicDNS at all, and if so, configure a valid upstream
  resolver before re-enabling `--accept-dns=true`.

### Cloudflared declarative rollout fix

Claude Code implemented a Kustomize `configMapGenerator` design:

- `config.yaml` contains the raw tunnel configuration.
- The old static `configmap.yaml` was removed.
- The cloudflared `kustomization.yaml` uses `configMapGenerator` with
  normal Kustomize hash suffix generation.
- The Deployment references the logical name `cloudflared-config`, which
  Kustomize rewrites to the hashed name automatically
  (e.g. `cloudflared-config-tt7c4hcgb8`).
- When `config.yaml` changes, Kustomize generates a new hash -> new
  ConfigMap name -> Deployment pod template changes -> Flux applies the
  change -> Kubernetes rolls cloudflared automatically -> new pod loads
  the new configuration.
- No `kubectl rollout restart` or manual pod deletion required. The
  configuration change itself is the declarative rollout trigger.
- Image pinned from `cloudflare/cloudflared:latest` to
  `cloudflare/cloudflared:2026.8.2@sha256:0aa26e284f...` (digest matched
  the already-running image, so no runtime upgrade was introduced).
- All existing ingress routes preserved (9 routes + catch-all 404).
- Hash behavior explicitly tested: temporary modification changed the
  hash, reverting restored the original hash.

### Samson Bash PROMPT_COMMAND fix

- Every shell command on Samson generated `syntax error near unexpected
  token ';;'` from a malformed `PROMPT_COMMAND`.
- Root cause: `~/.bashrc` set
  `PROMPT_COMMAND="history -a; history -c; history -r; $PROMPT_COMMAND"`
  which left a trailing `;` when `PROMPT_COMMAND` was empty. Zoxide then
  appended its hook, producing `history -a; history -c; history -r;;__zoxide_hook`.
- Fixed by changing to:
  `PROMPT_COMMAND="history -a; history -c; history -r${PROMPT_COMMAND:+; $PROMPT_COMMAND}"`
- Verified with `declare -p PROMPT_COMMAND`: history sync, Zoxide hook,
  and Oh My Posh hook all coexist correctly with no `;;`.

### Lessons learned

- See [[Kustomize ConfigMapGenerator Rollout Triggers]] for the GitOps
  ConfigMap rollout pattern.
- See [[Tailscale DNS SERVFAIL on Kubernetes Nodes]] for the DNS
  troubleshooting runbook.
- Local-path storage affects workload scheduling — pin workloads that
  share data to the same node.
- DNS failures can masquerade as container-registry failures. Test
  `getent hosts`, `dig`, and `curl` from the actual Kubernetes node.
- Preserve known-good workloads during investigation — the old cloudflared
  pod kept the tunnel alive while Samson was diagnosed.
- Bash `PROMPT_COMMAND` can be compositional — use `${VAR:+; $VAR}` to
  conditionally append delimiters.
